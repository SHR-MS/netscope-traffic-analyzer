## 二、真实抓包测试

用本机 Wi-Fi 网卡抓取约 50 秒日常流量，另存为 pcap 后再用程序打开：

| 指标 | 结果 |
|---|---|
| 文件大小 | 52.8 MB |
| 报文数 | 24,114 |
| 采集时长 | 49.9 秒（约 480 包/秒） |
| IPv4 / IPv6 / 其它 | 5,799 / 18,311 / 4 |
| 长度分段（≤46 / 47–1500 / >1500） | 2,213 / 16,570 / 5,331 |
| 截断 / 畸形 | 0 / 0 |

界面图表显示的三组数字与独立脚本对 pcap 的统计完全一致，长度分布折线图、
三段柱状图、IP 版本柱状图均正常。

**关于 >1500 字节的报文**：抓包网卡开启了接收端聚合（RSC），操作系统会把
连续 TCP 段合并后上交，Npcap 抓到的是合并后的帧，所以出现 2892、2940 字节的
记录。这不是解析错误，程序按 IP 头声明的总长度统计，口径不受影响。

## 四、异常告警测试

用 `tools/异常流量生成.py` 向同网段空闲地址发包（不打网关、不打公网），
一次完整测试触发 4 条告警：

| 时间 | 规则 | 级别 | 目标 | 证据 |
|---|---|---|---|---|
| 15:52:23 | SYN_FLOOD | critical | 10.195.175.253:80 | 5s 内 SYN 100 个（20/s），SYN-ACK 0 个，比值 100.0 |
| 15:52:27 | ICMP_ECHO_FLOOD | critical | 10.195.169.82 | 5s 内 echo request 50 个（10/s） |
| 15:52:39 | ICMP_ORPHAN_REPLY | warning | 10.195.169.82 | 5s 内 echo reply 20 个，而 echo request 仅 0 个 |
| 15:52:41 | ICMP_BIG_ECHO | info | 10.195.169.82 | echo request 载荷 1400 B，且分片 |

"次数"列等于各规则阈值（100 / 50 / 20），说明告警在刚越过阈值的瞬间触发，
随后进入 60 秒冷却，不会刷屏。

## 六、测试中发现并修复的问题

记录在这里，方便写报告时说明调试过程：

1. **pcap 滚动阈值不生效**：最初用 `Path.stat().st_size` 判断分段大小，
   但写入有缓冲、文件还没落盘时 size 一直偏小，导致从不切换分段。
   改为在写入器内部累计字节数。
2. **IPv6 片偏移单位算错**：分片头里的偏移字段单位是 8 字节，代码多乘了一次 8，
   导致偏移显示为实际值的 8 倍。改为 `(field >> 3) * 8`。
3. **批处理脚本闪退**：`if (...)` 块里出现了带右括号的路径，括号提前闭合导致
   cmd 解析失败，窗口一闪而过。改用 goto 标签避开括号块。
4. **测试工具发不出包**：`IP()/ICMP()/b"ping" * 8` 里 `/` 和 `*` 同级左结合，
   实际变成 `(包) * 8`（scapy 里"包 × 8"得到列表），`send()` 收到嵌套列表报错。
   给 `b"ping" * 8` 加括号解决。
5. **列表选中位置漂移**：报文超过 5000 行后旧行被挤出，详情树停在中途某条。
   改为"跟随最新报文，手动选中后暂停，滚回底部恢复"。
